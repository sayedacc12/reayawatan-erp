# النسخ الاحتياطي لسنابل

## كيف يعمل

- كل يوم الساعة 3 فجرًا بتوقيت الرياض يأخذ السيرفر نسخة من **قاعدة البيانات** و**الملفات المرفوعة**.
- النسخة **تُشفّر** ثم تُرفع **مباشرة** إلى وجهتين خارج السيرفر، ولا تُحفظ على قرص السيرفر:
  1. **Oracle Object Storage** (مجاني حتى 20 جيجا في حساب Oracle).
  2. **Google Drive** (نسخة ثانية احتياطية).
- يُحتفظ في كل وجهة بآخر **7 نسخ يومية** وآخر **4 نسخ أسبوعية** (نسخة يوم الجمعة)، ويُحذف الأقدم تلقائيًا. لا يُحذف شيء إلا بعد نجاح النسخة الجديدة.
- كل جمعة تُجرَّب **استعادة** آخر نسخة من كل وجهة في قاعدة مؤقتة ثم تُحذف، للتأكد أن النسخ سليمة فعلًا.
- النتائج تظهر لمدير المنصة في شاشة **إدارة المنصة ← النسخ الاحتياطي**، مع علامة حمراء ورسالة بريد للإدارة إذا فشلت نسخة أو تأخرت أكثر من 30 ساعة.

> **مفتاح التشفير:** يظهر مرة واحدة عند الربط. احفظه خارج السيرفر (ورقة أو مدير كلمات مرور).
> بدونه لا يمكن فتح أي نسخة إذا تعطل السيرفر. لا ترسله في أي محادثة.
> يمكن عرضه مرة أخرى على السيرفر بالأمر: `bash deploy/backup.sh show-key`

المؤقت اليومي يُجهَّز تلقائيًا عند تشغيل `deploy/setup.sh`. بقي فقط ربط الوجهتين مرة واحدة.

## أولًا: ربط Oracle Object Storage

### 1. إنشاء مكان التخزين (Bucket)
1. ادخل على لوحة Oracle Cloud.
2. من القائمة: **Storage ← Buckets**.
3. اختر الـ Compartment الرئيسي (root)، ثم **Create Bucket**.
4. الاسم: `sanabel-backups`، واترك باقي الخيارات كما هي (Standard، وخاص Private)، ثم **Create**.
5. افتح الـ Bucket، وانسخ قيمة **Namespace** الظاهرة في صفحته.

### 2. إنشاء مفتاح الدخول
1. من أيقونة الحساب أعلى اليمين: **My profile**.
2. من القائمة الجانبية: **Customer secret keys ← Generate secret key**.
3. الاسم: `sanabel-backup`، ثم **Generate**.
4. يظهر **Secret** مرة واحدة فقط. انسخه واحتفظ به مؤقتًا في مكان آمن على جهازك.
5. بعد الإغلاق يظهر المفتاح في القائمة، وبجانبه **Access Key**. انسخه أيضًا.

### 3. الربط على السيرفر
ادخل السيرفر، ثم:
```bash
cd charity-erp
bash deploy/backup.sh setup-oracle
```
سيطلب: Namespace، واسم الـ Bucket (اضغط Enter للقيمة الافتراضية)، والمنطقة (Enter)، ثم Access Key، ثم Secret Key (لا يظهر أثناء اللصق، وهذا طبيعي).
في أول ربط يظهر **مفتاح التشفير**: احفظه ثم اضغط Enter. ثم يجرب الربط ويكتب «الربط يعمل».

## ثانيًا: ربط Google Drive

1. اخرج من السيرفر، ثم ادخل بهذا الأمر (أضفنا له جزءًا يسمح لمتصفحك بإكمال الدخول إلى Google):
   ```bash
   ssh -L 53682:localhost:53682 -i <ملف المفتاح> ubuntu@<IP السيرفر>
   ```
2. ثم:
   ```bash
   cd charity-erp
   bash deploy/backup.sh setup-drive
   ```
3. يظهر رابط يبدأ بـ `http://127.0.0.1:53682/auth`. انسخه وافتحه في متصفح جهازك.
4. اختر حساب Google، ووافق. الصلاحية محدودة: يرى سنابل الملفات التي ينشئها هو فقط، ولا يرى بقية ملفاتك.
5. ترجع للسيرفر فتجده كتب «الربط يعمل». النسخ تُحفظ في Drive في مجلد `sanabel-backups`.

## ثالثًا: أول نسخة الآن
```bash
bash deploy/backup.sh run
```
ثم افتح **إدارة المنصة ← النسخ الاحتياطي** وتأكد أن الوجهتين «تعمل بانتظام».

## أوامر مفيدة

| الأمر | ماذا يفعل |
|---|---|
| `bash deploy/backup.sh list` | عرض النسخ الموجودة في كل وجهة |
| `bash deploy/backup.sh status` | آخر النتائج |
| `bash deploy/backup.sh verify` | تجربة استعادة آخر نسخة في قاعدة مؤقتة (لا يمس البيانات الحالية) |
| `bash deploy/backup.sh show-key` | عرض مفتاح التشفير |

## الاسترجاع (عند الحاجة فقط)

```bash
bash deploy/backup.sh list
bash deploy/backup.sh restore oracle 2026-11-20_0300
```
- اكتب `gdrive` بدل `oracle` للاسترجاع من Google Drive. وبدون اسم نسخة يُسترجع أحدثها.
- قبل الاستبدال يأخذ السكربت **نسخة أمان** من الوضع الحالي في مجلد `pre-restore` (يُحتفظ بآخر 3)، فيمكن التراجع.
- يوقف الخادم دقيقة، ويسترجع الملفات وقاعدة البيانات، ثم يشغّله. استرجاع القاعدة يتم كاملًا أو لا يتم.
- سجل النسخ الاحتياطي في الشاشة يبقى كما هو ولا يرجع لتاريخ النسخة.

### إذا تعطل السيرفر كاملًا
1. جهّز سيرفرًا جديدًا بخطوات `deploy/README.md` (ينتهي بـ `setup.sh`).
2. شغّل `bash deploy/backup.sh setup-oracle`، وعند سؤال المفتاح **الصق مفتاح التشفير القديم** بدل إنشاء جديد.
3. `bash deploy/backup.sh restore oracle`

## ملاحظات فنية
- الأداة المستخدمة: `rclone` (من مستودعات Ubuntu)، والتشفير بطبقة `crypt` فيها. أسماء الملفات ظاهرة (التاريخ فقط)، والمحتوى مشفّر.
- الإعدادات والمفاتيح في `/etc/sanabel-backup/` على السيرفر فقط، ولا يقرؤها إلا root، ولا تُرفع إلى GitHub.
- قاعدة البيانات تُنسخ بصيغة `pg_dump -Fc` (مضغوطة)، والملفات المرفوعة بصيغة `tar.gz`.
- المؤقت: `systemctl list-timers sanabel-backup.timer`، وسجل آخر تشغيل: `journalctl -u sanabel-backup -n 50`.
- تجربة الاستعادة الأسبوعية تستخدم مساحة مؤقتة بحجم القاعدة لدقائق ثم تُحذف.
- عند فشل نسخة أو تأخرها أو فشل تجربة الاسترجاع تصل رسالة واحدة لعناوين الإدارة في إعدادات البريد (يمكن إيقافها من «البريد الإلكتروني» ← الأحداث).
